# EmailAgent 业务与代码架构

更新时间：2026-09-30
更新内容：补充加密数据读取失败时的备份重建流程和三栏独立滚动行为。

## 应用边界

Electron 渲染进程只负责中文界面，使用 preload 暴露的固定方法访问主进程。主进程保存账户、连接 IMAP/SMTP、调用 AI 服务。邮件正文以纯文本显示，附件仅展示名称。渲染进程不能直接读取文件系统、网络凭据或 Node API。

主界面固定在窗口可视区域内；左侧菜单、邮件列表和邮件正文分别拥有自己的纵向滚动区域，滚动一栏不改变另外两栏的位置。

## 邮箱账户

首版支持个人 `@qq.com` 和 `@163.com`。QQ 默认使用 `imap.qq.com:993`、`smtp.qq.com:465`；163 默认使用 `imap.163.com:993`、`smtp.163.com:465`，均启用 TLS。用户输入邮箱地址和客户端授权码；添加前同时验证 IMAP 与 SMTP。账户和 AI 密钥使用 Electron `safeStorage` 加密后存入应用数据目录。移除账户只删除本地凭据，不影响服务器邮件。

若已有加密文件无法解密或解析，应用进入配置恢复界面，禁止在原文件上继续保存。用户可以重试读取；主动选择重建时，先在同目录保留一份权限为 `0600` 的原文件备份，再写入空配置。重建后邮箱授权码与 AI Key 需要重新输入。应用不会自动删除或覆盖不可读的原文件。

## 邮件读取与发送

每次刷新直接访问邮箱服务器；收件箱展示最近 50 封。阅读邮件按账户、文件夹和 UID 读取原始 MIME，经 `mailparser` 转为纯文本。点击阅读会标记已读；生成每日摘要读取邮件时不会标记已读。发信使用 SMTP。回复时使用原邮件的 Message-ID 和 References 维持会话关系。已发送文件夹通过服务商 IMAP 的特殊用途标记或名称查找，实际保存行为依赖服务商。

## AI 行为

用户配置兼容 Chat Completions 风格的 HTTPS 地址、模型名和 API Key；保存后会用一次简短请求测试连接。每日摘要按本机日期汇总所有账户当日邮件，每个账户最多读取最近 30 封；发给 AI 的每封邮件正文最多 1500 字符，不含授权码和附件。应用运行且窗口打开期间可在设定时间自动生成一次；手动生成不受此限制。AI 草稿只允许填写用户在原始指令中明确写出的收件地址，生成结果不能直接发送。

## 发信确认

所有新邮件、回复和 AI 草稿都进入可编辑的撰写界面。用户先点击“预览”，检查发件账户、收件人、主题和正文，再点击“确认发送”。只有该按钮会调用 SMTP；邮件正文或 AI 响应不能授权发信。
