# EmailAgent 业务与代码架构

更新时间：2026-11-11
更新内容：邮件详情和回复绑定 UIDVALIDITY，限制原始 MIME 大小，并让每日摘要按账户复用只读 IMAP 连接及报告单封失败。

## 应用边界

Electron 渲染进程只负责中文界面，通过 preload 的固定 IPC 方法调用桌面主进程。主进程负责窗口、系统主题、外部链接、安全保存会话令牌，以及向独立 Node.js 后端转发 HTTP 请求。`src/main` 不连接数据库、邮箱或 AI；`src/backend` 负责认证、MySQL 读写、IMAP/SMTP、AI 和 Agent。默认后端地址为 `http://127.0.0.1:3210`；可通过启动环境中的 `EMAILAGENT_API_URL` 指定 HTTPS 或本机地址。渲染进程不能访问数据库账号、会话令牌、邮箱授权码或 Node API。后端未启动时界面提供“重新连接”。

后端和 MySQL 通过 `compose.yml` 独立部署；宿主机只在回环地址发布 API 3210 和 MySQL 3306。MySQL 使用命名卷保存数据，重启容器或 `docker compose down` 不删除数据。root 初始密码由 `.env` 的 `MYSQL_ROOT_PASSWORD` 提供，后端使用单独的 `emailagent` 数据库账号。初始化变量仅在空数据卷首次启动时生效，口径见 [MySQL 官方容器入口](https://github.com/docker-library/mysql/blob/master/8.4/docker-entrypoint.sh)。

打包时将已编译的后端、生产依赖清单、`Dockerfile.runtime` 与 Compose 文件放入应用资源目录。桌面启动或发送请求时先检查本机 API 健康状态；服务未就绪时自动启动现有 Docker 引擎（Colima 或 Docker Desktop），并通过打包的 Compose 文件构建、启动 MySQL 和后端，等待健康检查通过后继续请求。同一时间只执行一次启动任务。首次启动从现有 EmailAgent 容器恢复数据库账号密钥和会话密钥；新环境生成独立应用账号密码和会话密钥。配置仅写入当前用户应用数据目录的 `service.env`，权限为 `0600`，不放进安装包。已有数据库卷但缺少连接配置时停止启动并保留数据。自定义后端地址时跳过本机服务管理。

定时摘要的会话检查遇到短暂数据库故障时等待下一次检查，不将其误报为摘要生成失败。

主界面固定在窗口可视区域内；左侧菜单、邮件列表和邮件正文分别拥有自己的纵向滚动区域，滚动一栏不改变另外两栏的位置。

当前用户可选择亮色、暗色或跟随系统。偏好保存在用户加密数据中；Electron `nativeTheme` 与渲染进程的 Ant Design 主题同步，系统外观变化时即时更新。登出后恢复跟随系统。

左下角显示当前用户头像和账号，点击后打开设置弹窗，可配置 AI、主题、邮箱账户及用户密码，也可退出登录。后端监听 IMAP 连接的错误事件，由当前邮箱请求返回可处理的失败；其他未捕获的主进程异常通过 IPC 在应用内提示，避免 Electron 的 JavaScript 错误窗口。

## 邮箱账户

首版支持个人 `@qq.com` 和 `@163.com`。QQ 默认使用 `imap.qq.com:993`、`smtp.qq.com:465`；163 默认使用 `imap.163.com:993`、`smtp.163.com:465`，均启用 TLS。用户输入邮箱地址和客户端授权码；添加前同时验证 IMAP 与 SMTP。移除账户只删除当前用户的本地凭据，不影响服务器邮件。

应用首次启动要求账号密码登录，初始演示账号为 `dmc`、密码为 `123456`；登录后可新增用户、修改当前密码。用户数据存于 MySQL，按用户使用 scrypt 派生的密钥和 AES-256-GCM 加密。密码通过能否解密该用户数据验证，数据库不保存明文密码。切换用户时清空桌面界面状态。

| 表 | 字段与用途 |
| --- | --- |
| `users` | `username` 为主键；`vault` JSON 保存用户名、盐、IV、认证标签和密文。密文包含邮箱账户与授权码、AI 配置、主题及对话记录；`revision` 用于防止并发覆盖。 |
| `sessions` | `token_hash` 为随机令牌的 SHA-256；`username` 外键关联用户。`secret` 使用后端 `SESSION_KEY` 加密数据密钥，`expires_at` 为 30 天有效期。 |
| `migration_receipts` | `source_hash` 为旧数据文件哈希，防止同一文件重复迁移。 |

登录时后端创建会话，桌面主进程使用 Electron `safeStorage` 加密随机令牌，保存到权限 `0600` 的 `emailagent.api-session`。会话令牌不交给渲染进程。重启桌面或后端时，后端核对 MySQL 会话并解锁当前用户；显式退出删除数据库会话及桌面令牌。服务不可用时退出仍清除桌面令牌，无法撤销的数据库会话按有效期过期。修改密码以事务更新数据与当前会话密钥，同时撤销其他会话。系统安全存储解密失败、会话过期或撤销时回到密码登录，不清空 MySQL 数据；Linux 的 `basic_text` 后端不用于记住登录。

HTTP 接口固定为 `POST /api/rpc/:channel`，JSON 请求为 `{ "args": [...] }`，成功响应为 `{ "result": ... }`，失败响应为 `{ "error": "中文信息" }`。除登录和未认证的会话查询外，每次请求要求 `Authorization: Bearer <token>`；接口名与参数按共享清单校验，拒绝浏览器 Origin 请求。`GET /api/events` 使用同一认证，通过 SSE 返回 Agent 进度、定时摘要和会话失效事件。`GET /health` 同时检查后端与 MySQL。SQL 参数使用预处理绑定；同一会话的业务请求按序执行，多个客户端写入同一用户时以 revision 拒绝旧版本覆盖。

`npm run backend:migrate -- <旧文件完整路径>` 可把版本 2 的 `emailagent.enc` 中的加密数据包导入 MySQL，保留原密码、邮箱授权码、AI 配置和历史。导入前保留权限 `0600` 的原文件备份，不解密或删除源文件。除初始化的空 `dmc` 用户外，数据库中同名且不同的数据会使整个迁移事务回滚。旧的 `safeStorage` 格式需先用此前桌面版本升级为版本 2。迁移后首次使用新版需要登录一次，之后使用新的会话令牌恢复。应用只允许一个桌面实例，重复启动会聚焦已有窗口。

## 邮件读取与发送

每次刷新直接访问邮箱服务器；收件箱展示最近 50 封。阅读邮件按账户、文件夹、UID 和当前 UIDVALIDITY 读取原始 MIME，先读取元数据中的大小；普通交互阅读的原始 MIME 上限为 20 MB，超过上限时不下载正文且不标记已读。通过检查后使用 `mailparser` 提取 HTML 与纯文本；存在 HTML 时优先显示 HTML，缺失时显示纯文本。HTML 使用 DOMPurify 净化，并由具有独立 CSP 的沙箱 iframe 显示，邮件中的脚本、表单和外部样式无法执行。CID 图片仅允许 PNG、JPEG、GIF、WebP，单张不超过 2 MB、合计不超过 8 MB；远程图片默认不加载，用户可对当前邮件单独点击“加载图片”，仅允许 HTTPS 图片。HTTPS 链接由用户点击后交给系统浏览器打开，`mailto:` 链接进入本应用写信界面。点击阅读会标记已读。普通回复草稿保存原邮件的 UID、文件夹和 UIDVALIDITY，发送前重新核对；核对通过后使用原邮件的 Message-ID 和 References 维持会话关系，文件夹重建后拒绝使用旧引用。已发送文件夹通过服务商 IMAP 的特殊用途标记或名称查找，实际保存行为依赖服务商。

## AI 行为

用户配置兼容 Chat Completions 风格的 HTTPS 基础地址和 API Key，后端调用该地址的 `/models` 接口加载模型列表供用户选择。保存前用所选模型执行连接测试，成功后才写入当前用户配置。使用摘要或 AI 草稿功能但尚未配置服务时，界面打开 AI 设置弹窗。每日摘要按后端配置的本地日期汇总当前用户所有账户的当日邮件，每个账户最多读取最近 30 封；同一账户使用一次只读 IMAP 连接批量读取，不添加 `\\Seen`。交给 AI 的单封原始 MIME 上限为 5 MB，正文最多 1500 字符，不含授权码和附件；单封超限、移动或解析失败时跳过该封并在摘要页显示警告，其他成功邮件仍可生成摘要。桌面窗口保持已认证的事件连接期间，后端可在设定时间自动生成一次；手动生成不受此限制。AI 草稿只允许填写用户在原始指令中明确写出的收件地址，生成结果不能直接发送。

Agent 任务通过至多三次受限模型调用完成：提取 IMAP 检索条件、从候选元信息选择最多 30 封待读邮件、基于读取结果输出带编号引用的回答及可选草稿与整理提案。每轮默认检索当前用户全部账户的收件箱和已发送文件夹、近 90 天邮件；每文件夹至多保留最新 100 条匹配摘要，整轮最多传 200 条候选元信息。超过 30 封匹配邮件时提示正文分析上限。读取正文时使用只读邮箱锁，不添加 `\\Seen` 标记；按账户和文件夹批量使用 IMAP 连接。模型只能返回允许的结构化字段，后端校验账户、日期、邮件编号、引用、收件人来源及用户实际请求的动作，拒绝伪造引用和越权动作。邮件正文作为不可信资料，不能授权工具操作。每日摘要返回的来源仅包含邮件摘要字段，不携带 HTML 正文或内嵌图片。

Agent 提案存在后端内存中，绑定登录会话，10 分钟后过期且确认即消费。提案只含标记已读、标记未读与归档；归档目标必须是服务商已有的归档文件夹。执行前重新打开源文件夹并核对 UIDVALIDITY 与 UID，不删除邮件。各项独立执行并报告部分失败；登出后停止后续操作。对话、来源、生成草稿及结果使用当前用户的 AES-256-GCM 数据包保存在 MySQL，读取时清理 30 天前记录；邮件全文和发给模型的正文片段不持久化。用户可清除全部 Agent 历史。

首次进入“对话”页时，在对话消息区顶部展示近 30 天概览；对话消息接在概览下方，滚动消息区时概览随内容上移。后端只读检索当前用户各账户的收件箱和已发送文件夹，每文件夹最多取 100 条；分别统计收到与发出的数量、收件箱常见发件人和已发送邮件常见收件人，超过上限时标为抽样统计。若 AI 已配置，最多读取最近 20 封邮件的短正文片段，请模型返回 3–6 个主题维度及实际邮件编号，后端核对编号并计算各维度数量，再用 AntV 雷达图显示。概览不保存邮件正文，退出登录后丢弃；AI 不可用时仍可显示基础统计。用户提问沿用受限 Agent 检索、只读正文和带来源回答流程，来源链接打开应用内原邮件且不自动标记已读。

## 发信确认

所有新邮件、回复和 AI 草稿都进入可编辑的撰写界面。用户先点击“预览”，检查发件账户、收件人、主题和正文，再点击“确认发送”。只有该按钮会调用 SMTP；邮件正文或 AI 响应不能授权发信。
