## 应用边界

Electron 渲染进程只负责中文界面，通过 preload 的固定 IPC 方法调用桌面主进程。主进程负责窗口、系统主题、外部链接、安全保存会话令牌，以及向独立 Node.js 后端转发 HTTP 请求。`src/main` 不连接数据库、邮箱或 AI；`src/backend` 负责认证、MySQL 读写、IMAP/SMTP、AI 和 Agent。默认后端地址为 `http://127.0.0.1:3210`；可通过启动环境中的 `EMAILAGENT_API_URL` 指定 HTTPS 或本机地址。渲染进程不能访问数据库账号、会话令牌、邮箱授权码或 Node API。后端未启动时界面提供“重新连接”。

后端和 MySQL 通过 `compose.yml` 独立部署；宿主机只在回环地址发布 API 3210 和 MySQL 3306。MySQL 使用命名卷保存数据，重启容器或 `docker compose down` 不删除数据。root 初始密码由 `.env` 的 `MYSQL_ROOT_PASSWORD` 提供，后端使用单独的 `emailagent` 数据库账号。初始化变量仅在空数据卷首次启动时生效，口径见 [MySQL 官方容器入口](https://github.com/docker-library/mysql/blob/master/8.4/docker-entrypoint.sh)。

打包时将已编译的后端、生产依赖清单、`Dockerfile.runtime` 与 Compose 文件放入应用资源目录。桌面启动或发送请求时先检查本机 API 健康状态；服务未就绪时自动启动现有 Docker 引擎（Colima 或 Docker Desktop），并通过打包的 Compose 文件构建、启动 MySQL 和后端，等待健康检查通过后继续请求。同一时间只执行一次启动任务。首次启动从现有 EmailAgent 容器恢复数据库账号密钥和会话密钥；新环境生成独立应用账号密码和会话密钥。配置仅写入当前用户应用数据目录的 `service.env`，权限为 `0600`，不放进安装包。已有数据库卷但缺少连接配置时停止启动并保留数据。自定义后端地址时跳过本机服务管理。

本地服务启动器按平台构造 Docker CLI 搜索路径：macOS 支持 Homebrew、Docker Desktop 与 Colima，Windows 支持 PATH、标准 `Program Files` 和当前用户 Docker 目录；Windows 引擎未运行时从标准位置隐藏启动 Docker Desktop。目标平台必须提供 Docker Compose v2 与 Linux 容器。会话安全存储在 macOS 使用当前用户钥匙串，在 Windows 使用当前用户 DPAPI；Linux 需要 Secret Service，检测到 `basic_text` 时不保存令牌。详细前置条件与故障边界见[平台打包文档](platform-packaging.md)。

`verify:package:mac` 与 `verify:package:win` 在对应操作系统使用临时用户目录和不可达的回环 API 启动目录包。验证窗口保持隐藏；只有打包主进程成功创建窗口且 preload 与 Renderer 完成加载后才写入临时就绪标记并以成功状态退出。验证不启动 Docker、不读取真实用户会话，结束后删除临时目录。CI 在 macOS 与 Windows runner 分别执行打包和此启动检查。

定时摘要的会话检查遇到短暂数据库故障时等待下一次检查，不将其误报为摘要生成失败。

主界面固定在窗口可视区域内；左侧菜单、邮件列表和邮件正文分别拥有自己的纵向滚动区域，滚动一栏不改变另外两栏的位置。

当前用户可选择亮色、暗色或跟随系统。偏好保存在用户加密数据中；Electron `nativeTheme` 与渲染进程的 Ant Design 主题同步，系统外观变化时即时更新。登出后恢复跟随系统。

左下角显示当前用户头像和账号，点击后打开设置弹窗，可配置 AI、主题、邮箱账户及用户密码，也可退出登录。后端监听 IMAP 连接的错误事件，由当前邮箱请求返回可处理的失败；其他未捕获的主进程异常通过 IPC 在应用内提示，避免 Electron 的 JavaScript 错误窗口。

主进程的 `DiagnosticsLogger` 在当前用户应用数据目录的 `diagnostics` 子目录保存 `emailagent.log`，单文件约 512 KB，保留当前文件与 2 代历史。日志仅记录生命周期事件、RPC 通道、耗时、成功/失败和错误类型，不写入参数、响应或底层错误文本。递归净化器按键排除授权码、密码、API Key、令牌、凭据、正文、HTML、草稿、Base64 和密文，文本净化器再遮盖 Bearer、`sk-` 风格密钥及 64 位十六进制令牌。设置页导出时由系统对话框选择目标，导出器等待写入队列完成并对全部历史再次全文脱敏；附加元信息只包含应用版本、平台、架构、运行时版本和是否打包，不包含用户名、邮箱地址或邮件内容。

## 邮箱账户

首版支持个人 `@qq.com` 和 `@163.com`。QQ 默认使用 `imap.qq.com:993`、`smtp.qq.com:465`；163 默认使用 `imap.163.com:993`、`smtp.163.com:465`，均启用 TLS。用户输入邮箱地址和客户端授权码；添加前同时验证 IMAP 与 SMTP。授权码更新只接收账户 ID 和新的候选值，先独立验证 IMAP 与 SMTP，全部成功后才在带 revision 校验的状态写入队列中替换 vault 凭据；失败、账户并发删除或会话变化均不写入。账户 ID、服务商和地址保持不变，需要更换邮箱身份时新增账户。只读健康检测返回收件、发件成功状态和检查时间，不返回底层错误或授权码；设置页密码框不回填旧值。移除账户只删除当前用户的本地凭据，不影响服务器邮件。

普通安装在空数据库首次启动时要求创建首位管理员，初始密码至少 8 位；创建操作以数据库行锁保证只能成功一次，并在成功后直接建立登录会话。只有显式设置 `EMAILAGENT_DEMO_MODE=1` 时，空数据库才创建演示账号 `dmc`、密码 `123456`，登录页同时显示演示模式警告；演示模式不得保存真实邮箱凭据。升级已有数据库时，根据已有用户把初始化状态设为完成，不新增、覆盖或重置 `dmc` 及其他用户。登录后可新增用户、修改当前密码。用户数据存于 MySQL，按用户使用 scrypt 派生的密钥和 AES-256-GCM 加密。密码通过能否解密该用户数据验证，数据库不保存明文密码。切换用户时清空桌面界面状态。

| 表 | 字段与用途 |
| --- | --- |
| `app_state` | 单行记录数据库是否已完成首位用户初始化；升级时若已有用户则自动标记完成。 |
| `users` | `username` 为主键；`vault` JSON 保存用户名、盐、IV、认证标签和密文。密文包含邮箱账户与授权码、AI 配置、主题、最近 20 条本地草稿、Agent 对话及最近 7 天摘要历史；`revision` 用于防止并发覆盖。 |
| `sessions` | `token_hash` 为随机令牌的 SHA-256；`username` 外键关联用户。`secret` 使用后端 `SESSION_KEY` 加密数据密钥，`expires_at` 为 30 天有效期。 |
| `migration_receipts` | `source_hash` 为旧数据文件哈希，防止同一文件重复迁移。 |

登录时后端创建会话，桌面主进程使用 Electron `safeStorage` 加密随机令牌，保存到权限 `0600` 的 `emailagent.api-session`。会话令牌不交给渲染进程。重启桌面或后端时，后端核对 MySQL 会话并解锁当前用户；显式退出删除数据库会话及桌面令牌。服务不可用时退出仍清除桌面令牌，无法撤销的数据库会话按有效期过期。修改密码以事务更新数据与当前会话密钥，同时撤销其他会话。系统安全存储解密失败、会话过期或撤销时回到密码登录，不清空 MySQL 数据；Linux 的 `basic_text` 后端不用于记住登录。

HTTP 接口固定为 `POST /api/rpc/:channel`，JSON 请求为 `{ "args": [...] }`，成功响应为 `{ "result": ... }`，失败响应为 `{ "error": "中文信息" }`。首次初始化状态查询、只能执行一次的管理员创建、登录和未认证的会话查询不要求令牌；其他请求要求 `Authorization: Bearer <token>`。登录失败按来源地址和规范化账号统计，10 分钟窗口内达到 5 次后阻止该组合 5 分钟；未知账号与错误密码统一返回“账号或密码错误”，不记录密码。接口名与参数按共享清单校验，拒绝浏览器 Origin 请求。`GET /api/events` 使用同一认证，通过 SSE 返回 Agent 进度、定时摘要和会话失效事件。`GET /health` 同时检查后端与 MySQL。SQL 参数使用预处理绑定；同一会话只把修改加密 vault 的短操作放入状态写入队列，邮件只读请求、摘要、概览和 Agent 长任务可并发。长任务提交结果时重新进入状态队列并刷新数据，多个客户端写入同一用户时继续以 revision 拒绝旧版本覆盖。

默认桌面和 Compose 只把后端发布到宿主机回环地址。远程部署必须由 TLS 反向代理提供 HTTPS，对外不得直接暴露后端明文 HTTP 或 MySQL；桌面客户端已经拒绝非本机的 HTTP 后端地址。反向代理到后端的内部地址、证书和访问控制由部署方管理。

`npm run backend:migrate -- <旧文件完整路径>` 可把版本 2 的 `emailagent.enc` 中的加密数据包导入 MySQL，保留原密码、邮箱授权码、AI 配置和历史。导入前保留权限 `0600` 的原文件备份，不解密或删除源文件。除初始化的空 `dmc` 用户外，数据库中同名且不同的数据会使整个迁移事务回滚。旧的 `safeStorage` 格式需先用此前桌面版本升级为版本 2。迁移后首次使用新版需要登录一次，之后使用新的会话令牌恢复。应用只允许一个桌面实例，重复启动会聚焦已有窗口。

## 邮件读取与发送

邮件读取直接访问邮箱服务器，不建立本地邮件索引；后端按账户、文件夹与查询在内存中缓存首屏页面和邮箱状态，桌面会话内前端再按账户保留已加载页面的快照。切换账户或文件夹时先立即显示快照，同时后台用 IMAP `STATUS` 核对 UIDVALIDITY、UIDNEXT、MESSAGES（服务端支持 CONDSTORE 时比较 HIGHESTMODSEQ）：状态未变化则复用缓存页；空查询下只有新增邮件时仅获取新增 UID 并合并到首屏；UIDVALIDITY 变化、邮件数量减少或带搜索条件时重新读取首屏。刷新按钮强制重读并覆盖缓存；标记已读同步更新缓存中的未读标记；发送邮件、更新授权码、删除账户和退出登录会使对应缓存失效。侧栏通过 IMAP 列出真实文件夹，保留服务端路径、稳定 ID、特殊用途、可选择和只读能力；界面不靠中文或英文名称猜测文件夹用途。首屏读取最新 50 封，继续加载使用绑定 UIDVALIDITY 和上一页最小 UID 的不透明游标，因此分页期间到达的新邮件不会挤乱已加载页；邮件被移动或删除造成缺项时返回可见警告。主题、发件人、起止日期和未读状态通过 IMAP 服务端搜索，最多保留最新 200 条匹配元信息，不下载整箱正文，也不建立本地或 AI 索引。每个账户在当前桌面会话中分别记住最后文件夹与查询；目录消失后回退到收件箱或首个可选择目录。会移动邮件的归档操作只信任服务端 `\Archive` 特殊用途标记，不按名称猜测目标。

阅读邮件按账户、文件夹、UID 和当前 UIDVALIDITY 读取原始 MIME，先读取元数据中的大小；普通交互阅读的原始 MIME 上限为 20 MB，超过上限时不下载正文且不标记已读。通过检查后使用 `mailparser` 提取 HTML 与纯文本；存在 HTML 时优先显示 HTML，缺失时显示纯文本。HTML 使用 DOMPurify 净化，并由具有独立 CSP 的沙箱 iframe 显示，邮件中的脚本、表单和外部样式无法执行。CID 图片仅允许 PNG、JPEG、GIF、WebP，单张不超过 2 MB、合计不超过 8 MB；远程图片默认不加载，用户可对当前邮件单独点击“加载图片”，仅允许 HTTPS 图片。普通附件在详情中只返回净化后的名称、类型、大小与受限编号，不返回字节；单件上限 10 MB、同一邮件解码后附件合计上限 20 MB。用户点击后主进程先打开系统保存对话框，再由后端重新核对账户、文件夹、UID、UIDVALIDITY 和附件编号并只读解析原始 MIME；主进程复核 Base64 解码大小后写入用户选择的位置。文件名移除目录、控制字符、跨平台保留字符与 Windows 设备名。HTTPS 链接由用户点击后交给系统浏览器打开，`mailto:` 链接进入本应用写信界面。点击阅读会标记已读。普通回复草稿保存原邮件的 UID、文件夹和 UIDVALIDITY，发送前重新核对；核对通过后使用原邮件的 Message-ID 和 References 维持会话关系，文件夹重建后拒绝使用旧引用。已发送文件夹通过服务商 IMAP 的特殊用途标记或名称查找，实际保存行为依赖服务商。摘要和 Agent 的模型输入只包含受限正文片段，不包含附件名称、类型或内容。

## AI 行为

用户配置兼容 Chat Completions 风格的基础地址和 API Key，后端调用该地址的 `/models` 接口加载模型列表供用户选择。远程地址只允许 HTTPS；本机回环地址（`127.0.0.1`、`localhost`、`::1`）允许使用 HTTP，用于 Ollama、LM Studio 等本地模型，此类地址可留空 API Key。开启“仅使用本机模型”后只接受回环地址，远程地址会被拒绝保存。保存前用所选模型执行连接测试，成功后才写入当前用户配置。使用摘要或 AI 草稿功能但尚未配置服务时，界面打开 AI 设置弹窗。桌面主进程在每次 RPC 和 SSE 连接中上报经后端验证的 IANA 时区；“今天”、当地午夜和执行时间均按该时区计算，不读取 Docker 的固定时区。每日摘要汇总当前用户所有账户的当日邮件，每个账户最多读取最近 30 封；同一账户使用一次只读 IMAP 连接批量读取，不添加 `\\Seen`。交给 AI 的单封原始 MIME 上限为 5 MB，正文最多 1500 字符，不含授权码和附件；单封超限、移动或解析失败时跳过该封并在摘要页显示警告，其他成功邮件仍可生成摘要。桌面窗口保持已认证的事件连接期间，后端在设定时间认领自动任务；运行锁阻止轮询重复启动，失败后按 1、5、15、30 分钟上限退避且每天最多尝试 4 次，只有成功写入历史后才视为当天完成。手动生成不受自动尝试上限限制。

AI 处理受四项独立开关控制：邮件摘要、起草邮件、对话检索、内容星图，关闭后对应功能在调用模型前直接拒绝或跳过，不读取正文。每次外发前在本地按主题与正文前 2000 字过滤疑似验证码、银行或账户安全类邮件，被过滤的邮件不会出现在模型输入中，摘要与 Agent 会显示跳过数量。后端只记录外发元信息（时间、功能、目标主机、邮件数量、字符数、成功与否、跳过数量），按用户保存在 vault 中，最多 20 条，可在设置中查看和清除，不记录邮件正文、地址或 API Key。自动摘要除时间、地址和模型外还要求摘要开关开启。

成功摘要以“当地日期 + 手动/自动方式”去重后写入当前用户 AES-256-GCM vault，保存摘要内容、来源摘要字段、生成时间和执行方式，清理 7 天前记录。持久化净化器只复制 UID、账户、文件夹、发件人、主题、日期和未读状态，不保存邮件正文、HTML、附件、内嵌图片或发送给模型的片段。同一当地日期最多一份有效自动结果；后端或桌面重连后从历史恢复该状态，避免重复生成。摘要页显示最近成功时间、执行方式、历史选择和失败后的手动重试入口。摘要正文与 Agent 回答按 Markdown 渲染（标题、列表、表格、代码块），正文中的链接交给系统浏览器，`mailto:` 进入写信界面；Agent 回答里的 `[n]` 编号是可点击的来源邮件入口。AI 草稿只允许填写用户在原始指令中明确写出的收件地址，生成结果不能直接发送。

Agent 任务由模型驱动的工具调用循环完成：模型每一轮只返回一个 JSON 动作，可调用 `list_folders`（列出文件夹）、`search_mail`（按账户、时间、发件人、主题、全文或未读条件检索收件箱与已发送）、`read_mail`（按编号读取正文，单次至多 10 封）、`draft_reply`（生成回复草稿）与 `propose_actions`（提出整理动作），或返回 `final` 结束任务；循环至多 8 步。每轮把当前候选邮件（编号、账户、发件人、主题、日期、文件夹、未读、是否已读正文）与最近 6 次工具结果回灌模型，默认检索当前用户全部账户近 90 天邮件；每文件夹至多保留最新 100 条匹配摘要，整轮最多收集 200 条候选元信息。读取正文使用只读邮箱锁，不添加 `\Seen` 标记，按账户与文件夹批量读取。模型只能返回允许的工具与结构化字段，后端校验账户、日期、邮件编号、引用、收件人来源及用户实际请求的动作，拒绝未知工具、伪造引用和越权动作；连续三次工具失败或超过步数上限即终止；若此时还没有检索到任何候选邮件，则直接返回“未找到匹配邮件”的说明而不是报错。邮件正文是不可信资料，不能授权工具操作。每次工具调用都会先发出 `stage: tool` 的进度事件（含步骤 id、工具、标签、说明与运行状态），执行完再发成功或失败状态，界面据此实时显示 Agent 正在做什么；任务完成后步骤随回答写入历史，在消息中折叠展示。每日摘要返回的来源仅包含邮件摘要字段，不携带 HTML 正文或内嵌图片。

Agent 提案存在后端内存中，绑定登录会话，10 分钟后过期且确认即消费。提案只含标记已读、标记未读与归档；归档目标必须是服务商已有的归档文件夹。执行前重新打开源文件夹并核对 UIDVALIDITY 与 UID，不删除邮件。各项独立执行并报告部分失败；登出后停止后续操作。对话、来源、生成草稿及结果使用当前用户的 AES-256-GCM 数据包保存在 MySQL，读取时清理 30 天前记录；邮件全文和发给模型的正文片段不持久化。用户可清除全部 Agent 历史。

桌面为每次 Agent 请求生成 UUID job id，后端为该任务创建 `AbortController`。取消信号与模型请求的 45 秒超时组合，并在每次模型调用、工具执行及最终持久化前后调用 `ensureActive()`。同一会话一次只接受一个 Agent 任务，第二个请求立即失败；`agent:cancel` 重复调用或任务已经结束时安全返回。主动取消、清空历史、登出、会话撤销和服务关闭都会中止任务；中止后禁止继续发进度事件、写入对话或创建整理提案。任务最终历史写入使用状态队列，因此不会绕过 vault revision 乐观并发控制。

首次进入“对话”页时，在对话消息区顶部展示近 30 天概览；对话消息接在概览下方，滚动消息区时概览随内容上移。后端只读检索当前用户各账户的收件箱和已发送文件夹，按检索结果总数精确统计收到与发出的数量，不受单次抓取 100 条上限影响；常见发件人和常见收件人取自每个文件夹最近的 100 封，超出部分不计入人员统计。概览结果按用户缓存在后端内存中，同一自然日内且账户列表未变化时，进入对话页或切换页面后直接返回缓存，不再连接邮箱；点击“刷新”强制重新检索并覆盖缓存，发信、确认 Agent 操作、增删账户、退出登录或跨天后缓存失效。若 AI 已配置，最多读取最近 20 封邮件的短正文片段，请模型返回 3–6 个主题维度及实际邮件编号，后端核对编号并计算各维度数量，再用 AntV 雷达图显示。概览不保存邮件正文，退出登录后丢弃；AI 不可用时仍可显示基础统计。用户提问沿用受限 Agent 检索、只读正文和带来源回答流程，来源链接打开应用内原邮件且不自动标记已读。

## 发信确认

所有新邮件、回复和 AI 草稿都进入可编辑的撰写界面。草稿把收件、抄送和密送分别保存为地址数组，合计最多 50 个；后端逐地址校验，并按不区分大小写的地址在 `to/cc/bcc` 之间去重后交给 Nodemailer。vault 读取器把旧版 `to: string` 自动迁移为单元素数组，为旧本地草稿和 Agent 历史补空 `cc/bcc`。用户可把未完成内容保存为本地草稿；后端校验字段和回复引用，按更新时间去重后最多保留 20 条，随当前用户 AES-256-GCM vault 写入 MySQL。加载草稿后继续编辑会重新进入未保存状态；关闭撰写窗口或 Electron 应用窗口前必须确认是否放弃修改。删除邮箱账户时删除其草稿。用户先点击“预览”，检查发件账户、全部收件地址、主题和正文，再点击“确认发送”。只有该按钮会调用 SMTP；邮件正文或 AI 响应不能授权发信。已保存草稿发送成功后删除对应记录；若 SMTP 已成功但清理失败，界面必须按“已发送”处理并提示手动清理，不能引导重复发送。
