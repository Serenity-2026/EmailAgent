# EmailAgent 业务与代码架构

更新时间：2026-09-30
更新内容：补充用户主题设置、近期邮箱概览与内容星图，以及对话页的邮件检索引用链路。

## 应用边界

Electron 渲染进程只负责中文界面，使用 preload 暴露的固定方法访问主进程。主进程保存账户、连接 IMAP/SMTP、调用 AI 服务。HTML 邮件经净化后在禁用脚本的沙箱 iframe 中按原有排版显示；纯文本邮件直接显示文本。附件仅展示名称。渲染进程不能直接读取文件系统、网络凭据或 Node API。除登录、会话状态和旧数据恢复外，主进程 IPC 操作要求当前用户已登录。

主界面固定在窗口可视区域内；左侧菜单、邮件列表和邮件正文分别拥有自己的纵向滚动区域，滚动一栏不改变另外两栏的位置。

当前用户可选择亮色、暗色或跟随系统。偏好保存在用户加密数据中；Electron `nativeTheme` 与渲染进程的 Ant Design 主题同步，系统外观变化时即时更新。登出后恢复跟随系统。

## 邮箱账户

首版支持个人 `@qq.com` 和 `@163.com`。QQ 默认使用 `imap.qq.com:993`、`smtp.qq.com:465`；163 默认使用 `imap.163.com:993`、`smtp.163.com:465`，均启用 TLS。用户输入邮箱地址和客户端授权码；添加前同时验证 IMAP 与 SMTP。移除账户只删除当前用户的本地凭据，不影响服务器邮件。

应用启动后要求本地账号密码登录。初始演示账号为 `dmc`、密码为 `123456`；登录后可新增本地用户、修改当前密码。邮箱账户、授权码和 AI 配置均保存在当前用户的加密数据中，切换用户时清空内存中的账户、邮件与 AI 状态。每个用户的数据以随机盐从登录密码派生密钥，使用 AES-256-GCM 加密；磁盘文件只存用户名、盐、随机数、认证标签与密文。初始账号密码仅用于首次建立用户数据文件；后续登录以密文认证，不在数据文件中保存明文密码。修改密码会用新密钥重新加密当前用户数据。

旧版 `safeStorage` 文件在初始用户首次登录时迁移到用户加密数据；迁移前先保留原文件备份。若旧文件无法解密或解析，登录后进入恢复界面，禁止覆盖原文件。用户可以重试读取；主动选择重建时，先在同目录保留一份权限为 `0600` 的备份，再写入空配置。重建后邮箱授权码与 AI Key 需要重新输入。添加邮箱不依赖 AI 配置，且新格式后续读写不再调用 `safeStorage`。应用只允许一个实例运行，重复启动会聚焦已有窗口。

## 邮件读取与发送

每次刷新直接访问邮箱服务器；收件箱展示最近 50 封。阅读邮件按账户、文件夹和 UID 读取原始 MIME，经 `mailparser` 提取 HTML 与纯文本；存在 HTML 时优先显示 HTML，缺失时显示纯文本。HTML 使用 DOMPurify 净化，并由具有独立 CSP 的沙箱 iframe 显示，邮件中的脚本、表单和外部样式无法执行。CID 图片仅允许 PNG、JPEG、GIF、WebP，单张不超过 2 MB、合计不超过 8 MB；远程图片默认不加载，用户可对当前邮件单独点击“加载图片”，仅允许 HTTPS 图片。HTTPS 链接由用户点击后交给系统浏览器打开，`mailto:` 链接进入本应用写信界面。点击阅读会标记已读；生成每日摘要读取邮件时不会标记已读，且仅传纯文本给 AI。发信使用 SMTP。回复时使用原邮件的 Message-ID 和 References 维持会话关系。已发送文件夹通过服务商 IMAP 的特殊用途标记或名称查找，实际保存行为依赖服务商。

## AI 行为

用户配置兼容 Chat Completions 风格的 HTTPS 基础地址和 API Key，主进程调用该地址的 `/models` 接口加载模型列表供用户选择。保存前用所选模型执行连接测试，成功后才写入当前用户配置。使用摘要或 AI 草稿功能但尚未配置服务时，界面打开 AI 设置弹窗。每日摘要按本机日期汇总当前用户所有账户的当日邮件，每个账户最多读取最近 30 封；发给 AI 的每封邮件正文最多 1500 字符，不含授权码和附件。应用运行且窗口打开期间可在设定时间自动生成一次；手动生成不受此限制。AI 草稿只允许填写用户在原始指令中明确写出的收件地址，生成结果不能直接发送。

Agent 任务通过至多三次受限模型调用完成：提取 IMAP 检索条件、从候选元信息选择最多 30 封待读邮件、基于读取结果输出带编号引用的回答及可选草稿与整理提案。每轮默认检索当前用户全部账户的收件箱和已发送文件夹、近 90 天邮件；每文件夹至多保留最新 100 条匹配摘要，整轮最多传 200 条候选元信息。超过 30 封匹配邮件时提示正文分析上限。读取正文时使用只读邮箱锁，不添加 `\\Seen` 标记；按账户和文件夹批量使用 IMAP 连接。模型只能返回允许的结构化字段，主进程校验账户、日期、邮件编号、引用、收件人来源及用户实际请求的动作，拒绝伪造引用和越权动作。邮件正文作为不可信资料，不能授权工具操作。每日摘要返回的来源仅包含邮件摘要字段，不携带 HTML 正文或内嵌图片。

Agent 提案存在主进程内存中，绑定登录会话，10 分钟后过期且确认即消费。提案只含标记已读、标记未读与归档；归档目标必须是服务商已有的归档文件夹。执行前重新打开源文件夹并核对 UIDVALIDITY 与 UID，不删除邮件。各项独立执行并报告部分失败；登出后停止后续操作。对话、来源、生成草稿及结果使用当前用户的 AES-256-GCM 数据文件保存，读取时清理 30 天前记录；邮件全文和发给模型的正文片段不持久化。用户可清除全部 Agent 历史。

首次进入“与邮箱对话”页时展示近 30 天概览。主进程只读检索当前用户各账户的收件箱和已发送文件夹，每文件夹最多取 100 条；分别统计收到与发出的数量、收件箱常见发件人和已发送邮件常见收件人，超过上限时标为抽样统计。若 AI 已配置，最多读取最近 20 封邮件的短正文片段，请模型返回 3–6 个主题维度及实际邮件编号，主进程核对编号并计算各维度数量，再用 AntV 雷达图显示。概览不保存邮件正文，退出登录后丢弃；AI 不可用时仍可显示基础统计。用户提问沿用受限 Agent 检索、只读正文和带来源回答流程，来源链接打开应用内原邮件且不自动标记已读。

## 发信确认

所有新邮件、回复和 AI 草稿都进入可编辑的撰写界面。用户先点击“预览”，检查发件账户、收件人、主题和正文，再点击“确认发送”。只有该按钮会调用 SMTP；邮件正文或 AI 响应不能授权发信。
