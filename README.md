# EmailAgent

更新时间：2026-10-07
更新内容：补充从 GitHub 下载桌面安装包及从源码启动的步骤。

面向课程作业的 Electron 桌面邮件助手，支持 QQ/163 邮箱、每日 AI 摘要、一句话写邮件与带来源的 Agent 对话。中文桌面界面连接独立 Node.js 后端，用户数据与会话保存在 Docker MySQL 中。邮箱授权码和 AI Key 按用户加密；使用 AI 功能时，所选邮件片段发送给用户配置的模型服务。

## 使用桌面应用

1. 在 Apple Silicon Mac 上安装 Docker Desktop，或安装 Docker Engine/Compose 与 Colima。应用会自动启动已安装的 Docker 环境。
2. 从 [GitHub Releases](https://github.com/Serenity-2026/EmailAgent/releases/latest) 下载 `EmailAgent-mac-arm64-one-click-20261007.zip`，解压后双击 `EmailAgent.app`。
3. 等待应用自动启动 MySQL 和后端。首次启动需要联网获取 MySQL 和 Node 基础镜像；随后使用初始账号 `dmc`、密码 `123456` 登录。已有用户使用原密码，登录状态会自动恢复。

服务不可用时，应用内可点击“重新连接”。MySQL 数据保存在 Docker 命名卷中，关闭应用或重启电脑不会清空数据。

## 从源码启动

需要 Node.js 22 或更新版本、npm 和可用的 Docker Engine/Compose。克隆仓库后，在项目目录执行：

```bash
npm ci
cp .env.example .env
```

在 `.env` 填入 MySQL root 初始密码、独立的应用数据库密码和 `SESSION_KEY`。`SESSION_KEY` 可用 `openssl rand -base64 32` 生成；后续重启保留这个值，以恢复有效登录会话。`.env` 不提交到 Git。

```bash
npm run services:up
npm run dev
```

`services:up` 在源码开发时启动 MySQL 和后端，并等待健康检查。桌面安装包会自动完成该步骤。默认 API 为 `127.0.0.1:3210`，MySQL 为 `127.0.0.1:3306`，数据库名 `emailagent`。后端也可单独部署。

```bash
npm run services:down
```

停止服务保留 MySQL 命名卷；不要使用 `docker compose down -v`，它会删除数据库卷。

## 迁移旧数据

已有版本 2 的用户加密文件可迁入数据库：

```bash
npm run backend:migrate -- '/Users/你的账号/Library/Application Support/EmailAgent/emailagent.enc'
```

迁移保留原密码、邮箱与 AI 配置、主题和对话记录；源文件先备份并保留。相同文件重复导入不会重复创建用户；已有同名且不同的数据库用户会阻止迁移。旧 `safeStorage` 格式应先使用之前版本升级。迁移后在新桌面应用登录一次，之后可以自动恢复。

## 开发与验证

```bash
npm run typecheck
npm test
npm run test:backend
npm run build
npm run package:mac
```

`test:backend` 使用 `.env` 中的 root 凭据创建隔离测试数据库，结束后删除测试数据库，不使用正式用户数据。`npm run package:mac` 在 `release/mac-arm64/EmailAgent.app` 生成可双击的应用。

后端代码在 `src/backend`，Electron 系统代码在 `src/main`，React 界面在 `src/renderer`，共享 API 与数据契约在 `src/shared`。需要在宿主机调试后端时：

```bash
npm run backend:build
npm run backend:start
```

先停止 Compose 的后端容器，避免占用相同端口。桌面可通过启动环境变量 `EMAILAGENT_API_URL` 指定 HTTPS 或本机 API 地址。

## 邮箱和 AI 设置

点击左下角头像打开设置，添加 QQ 或 163 邮箱；先在服务商网页启用 IMAP/SMTP，再填完整邮箱地址和客户端授权码。保存前验证收信与发信连接。不要输入网页登录密码。

在 AI 设置填入兼容 Chat Completions 的 HTTPS `base_url` 和 API Key，加载模型列表后选择模型并保存。数据库按用户加密保存邮箱授权码和 AI 配置。退出登录会撤销后端会话；修改密码会撤销其他会话。

## 功能范围

- 邮件列表最近 50 封；每日摘要每账户最多读取最近 30 封当日邮件。
- “对话”默认检索全部邮箱近 90 天的收件箱与已发送，回答附可点击的原邮件来源。
- 对话区顶部展示近 30 天收发数量、往来人和内容星图；主题分析最多读取最近 20 封邮件片段。
- Agent 可提议标记已读、标记未读和归档，确认后执行并逐项报告；归档需要服务商已有归档文件夹。
- 对话记录按用户加密保留最近 30 天，不持久保存邮件全文或模型收到的正文片段。
- 邮件 HTML 经净化与沙箱显示；远程图片按封手动加载；附件只显示名称。
- 所有发信先编辑、预览，再由用户点击“确认发送”。
- 亮色、暗色和系统主题偏好存于当前用户数据中。

产品规格见 [SPEC.md](SPEC.md)，数据表、API 与业务边界见 [doc/architecture.md](doc/architecture.md)。

### 0.1.3 - M1 邮件引用与读取管线（2026-11-11）

- 普通邮件详情现在携带邮箱文件夹 UIDVALIDITY；回复发送前同时核对文件夹、UID 和 UIDVALIDITY，文件夹重建后拒绝沿用旧引用。
- 每日摘要对每个邮箱只建立一次只读 IMAP 连接，在同一锁内读取最多 30 封邮件，不会因为摘要而标记已读。
- 普通阅读在下载正文前检查原始 MIME 大小，上限为 20 MB；AI 摘要和 Agent 正文读取上限为 5 MB。
- 摘要批量读取中单封邮件超限、移动或解析失败时跳过该封，并在摘要页展示警告，其余邮件仍可用于生成摘要。
- 新增 UIDVALIDITY、超大 MIME、单连接批量读取、部分失败和不标已读回归测试。

### 0.1.4 - S1 安全首次初始化（2026-11-11）

- 普通安装的空数据库不再预置公开密码账户，首次启动改为在桌面创建首位管理员，初始密码至少 8 位。
- 如需课程演示，在 `.env` 显式设置 `EMAILAGENT_DEMO_MODE=1`；仅空数据库会创建 `dmc / 123456`，登录页会显示演示模式警告。
- 已有数据库升级时自动识别为已初始化，不新增、覆盖或重置已有用户、密码、会话和加密数据。
- 登录失败按来源和账号统计，10 分钟内达到 5 次后限制 5 分钟；未知账号与错误密码继续使用相同提示。
- 后端默认只发布到本机回环地址；远程使用必须通过 TLS 反向代理提供 HTTPS，不得直接暴露后端 HTTP 或 MySQL。
- 新增首次初始化、重复初始化拒绝、旧数据库升级、限流恢复、会话重启保持和演示模式界面测试。

### 0.1.5 - A1 可取消 Agent 任务（2026-11-11）

- 同一会话不再把邮件读取和长 Agent 任务塞进单一队列；短状态写入继续串行，历史保存仍使用 MySQL revision 防止覆盖。
- 每个 Agent 任务带独立 job id 和 `AbortController`，规划、邮件检索、正文选择及最终回答阶段都会检查任务与会话状态。
- 新增 `agent:cancel` 接口；运行时可点击“取消任务”，页面会保留完成、失败或已取消的最终状态，重复取消安全返回。
- 第二个 Agent 请求不会等待前一任务结束，而是立即提示先取消或等待；清空历史、登出、会话失效和服务关闭也会中止任务。
- 模型 HTTP 请求使用任务取消信号与 45 秒超时的组合信号；取消后不保存半成品对话，也不生成待确认整理提案。
- 新增邮件读取并发、规划/检索/回答阶段取消、重复任务、清空历史、登出以及取消按钮回归测试。

### 0.1.6 - D1 可靠每日摘要（2026-11-12）

- 桌面 RPC 与事件连接会上报当前 IANA 时区，后端据此计算“今天”、当地午夜和每日执行时间，不再依赖 Docker 容器的固定时区。
- 自动摘要使用运行锁和有界退避：失败后按 1、5、15 分钟等间隔重试，每天最多尝试 4 次，成功前不会把当天永久标记完成。
- 最近 7 天摘要随当前用户 vault 加密保存到 MySQL，记录来源元信息、生成时间和手动/自动方式；邮件正文、HTML 和模型输入片段不会写入历史。
- 摘要页可选择最近历史，显示最近成功时间与生成方式；自动或手动失败时提供“立即重试”入口。
- 同一用户同一天的自动结果在调度和持久化两层去重，后端或桌面重连后会读取历史并避免重复生成。
- 新增时区跨零点、夏令时、跨日运行、退避上限、重连去重、历史净化、会话时区上报和摘要页面回归测试。

### 0.1.7 - B1 邮箱导航、分页与搜索（2026-11-12）

- 新增真实 IMAP 文件夹列表，展示收件箱、已发送、草稿、归档、垃圾邮件等服务端目录，并携带稳定 ID、特殊用途、可选择和只读能力。
- 邮件列表改为 UID 游标分页：首屏保持 50 封，可继续加载更早邮件；游标绑定 UIDVALIDITY，文件夹重建后要求刷新。
- 新增主题、发件人、起止日期和已读状态的 IMAP 服务端搜索，最多返回最近 200 条匹配元信息，不下载整箱正文，也不建立本地或 AI 索引。
- 每个账户分别记住最后打开的文件夹和查询条件；目录消失时安全回退到收件箱或首个可用目录。
- 分页期间新增邮件不会挤乱已加载页，Renderer 按文件夹与 UID 去重；邮件移动或删除造成缺项时显示警告，不再静默跳过。
- 新增 QQ/163 文件夹差异、只读/不可选择能力、搜索截断、稳定分页、UIDVALIDITY 失效、账户切换记忆和继续加载测试。

### 0.1.8 - C1 账户维护与连接健康（2026-11-12）

- 设置页按账户分别展示 IMAP 收件和 SMTP 发件连接状态，并记录最近一次检查时间。
- 授权码失效后可直接输入新授权码；后端先同时验证 IMAP/SMTP，全部通过后才原子替换加密 vault 中的旧凭据。
- 验证失败、账户在验证期间被删除或登录会话发生变化时拒绝写入，不会覆盖旧授权码或恢复已删除账户。
- 更新 API 只接受账户 ID 与新授权码，邮箱地址和服务商不可原地修改，避免账户 ID 与历史邮件引用失配。
- 健康状态与更新响应不包含授权码或服务商底层错误；界面的密码框始终为空，不回显已保存值。
- 新增双通道健康、成功更新、失败回滚、并发删除、会话变化、MySQL 持久化和设置页操作回归测试。

### 0.1.9 - O1 本地加密草稿（2026-11-12）

- 撰写窗口可保存、载入和删除本地草稿，最近 20 条随当前用户数据一起使用 AES-256-GCM 加密存入 MySQL vault。
- 草稿字段与回复引用在读写时经过边界校验；无效、重复或超过上限的记录不会进入可用列表。
- 编辑已保存草稿后关闭撰写窗口会提示未保存修改，避免静默丢失正文。
- Renderer 把未保存状态同步到 Electron 主进程，关闭应用窗口时提供“继续编辑/放弃修改并关闭”确认。
- 已保存草稿发送成功后自动删除；发送成功但清理失败时明确提示用户手动删除，避免误认为邮件未发出。
- 删除邮箱账户时同步清理其本地草稿；新增 vault 上限、加密持久化、恢复、删除、关闭提示和发送后清理测试。

### 0.1.10 - O1 多收件人、抄送与密送（2026-11-12）

- 发信草稿从单个收件人字符串升级为数组型 `to/cc/bcc`，普通撰写、回复、AI 草稿和 Agent 回复统一使用同一结构。
- 撰写窗口增加抄送和密送输入，三个字段均支持使用逗号、分号或换行分隔多个完整邮箱地址。
- 后端逐地址校验，最多接受 50 个地址，并按不区分大小写的地址在收件、抄送、密送之间去重。
- SMTP 调用分别传递 `to`、`cc`、`bcc` 数组；密送地址由 Nodemailer 按邮件协议处理，不拼入普通收件人字符串。
- AI 只能保留用户指令中明确出现的邮箱地址，不能借多收件人字段引入额外地址。
- vault 读取兼容旧版 `to: string`，自动迁移本地草稿和最近 30 天 Agent 历史草稿并补齐空的 `cc/bcc`；新增迁移、UI、API 和 SMTP 测试。

### 0.1.11 - O1 安全附件下载（2026-11-12）

- 邮件详情只展示附件名称、类型、解码后大小和可下载状态，不把附件字节交给 Renderer。
- 用户点击附件后先通过 Electron 系统对话框选择保存位置；取消选择不会请求或写入附件内容。
- 下载前重新核对账户、文件夹、UID、UIDVALIDITY 和附件编号，邮件移动或文件夹重建后要求重新打开邮件。
- 单个附件上限为 10 MB，同一邮件附件解码后合计上限为 20 MB；超限项在界面禁用并说明原因。
- 文件名移除路径、控制字符、跨平台保留字符和 Windows 设备名风险，主进程写盘前再次核对实际字节数。
- 每日摘要与 Agent 仍只接收必要正文片段，不传附件名称或内容；新增策略、MIME 下载、文件名、会话/API 和界面回归测试。

### 0.1.12 - O1 脱敏诊断与一键导出（2026-11-12）

- Electron 主进程在当前用户应用数据目录保存本地诊断日志，单文件约 512 KB，最多保留当前文件及 2 代轮转文件。
- 日志只记录应用生命周期、RPC 通道、成功/失败类别和耗时，不记录 RPC 参数、返回值或底层服务错误正文。
- 递归脱敏授权码、密码、API Key、会话令牌、凭据、邮件正文、HTML、草稿、Base64 和密文等敏感键。
- 文本层额外遮盖 Bearer 值、`sk-` 风格密钥和 64 位十六进制会话令牌；导出文件生成前再次执行全文脱敏。
- 设置页新增“导出诊断信息”，由系统对话框选择位置；导出只附带应用版本、平台、架构和运行时版本等非用户数据。
- 新增嵌套敏感值、令牌模式、轮转上限、导出二次脱敏和设置页入口回归测试。
